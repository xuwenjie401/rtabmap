## Coordinate Frames

Frame names:

```text
map                         RTAB-Map optimized global map frame
oak                         OAK base frame used by RTAB-Map odometry
oak_rgb_camera_optical_frame RGB camera optical frame
```

`map` is gravity-aligned from RTAB-Map stereo+IMU processing. Treat it as the global z-up map frame for this dataset.

RGB optical frame convention is ROS optical:

```text
+x right in image
+y down in image
+z forward through image plane
```

The exporter obtains `T_oak_rgb_camera_optical_frame` from `/tf_static`. The current value is saved in `metadata.json` as `T_base_rgb_optical`, row-major 4x4.

## Point Clouds

For the high-resolution export, the recommended default map cloud is the latest `/rtabmap_highres/cloud_map` from the high-resolution cloud bag, in frame `map`.

For the baseline export, the map cloud is the latest `/rtabmap/cloud_map` from the processed bag.

Downstream code should prefer `metadata.json -> cloud_exports` to locate the cloud file instead of hard-coding a filename. Select the entry whose `topic` ends with `/cloud_map`, then read its `npz_path` or `ply_path`.

The matching `.npz` file contains:

```text
xyz:       float32 [N, 3], meters, frame=map
rgb:       uint8   [N, 3], may be empty if source cloud has no color
intensity: float32 [N], may be empty
```

For the baseline export:

```text
rtabmap_cloud_map_latest.npz       xyz shape = [263919, 3], rgb present
rtabmap_cloud_obstacles_latest.npz xyz shape = [213217, 3], rgb present
rtabmap_cloud_ground_latest.npz    xyz shape = [50702, 3], rgb present
```

The high-resolution cloud is also derived from RTAB-Map map manager output, but it is regenerated from `/rtabmap/mapData` by `rtabmap_util/map_assembler` using finer local-grid settings. This is intended to be closer to the point-cloud quality seen in `rtabmap_viz`.

The current high-resolution assembly settings were:

```text
Grid/CellSize = 0.02
Grid/DepthDecimation = 1
Grid/PreVoxelFiltering = false
Grid/RangeMin = 0.2
Grid/RangeMax = 5.0
Grid/NormalsSegmentation = true
Grid/MinClusterSize = 10
cloud_output_voxelized = true
cloud_subtract_filtering = false
```

If a denser or less voxelized comparison cloud is needed, regenerate the high-resolution cloud bag with `Grid/CellSize=0.015` or `cloud_output_voxelized=false`, then export again with `--cloud-bag`.

## Pose Generation Method

The RGB poses are not simply nearest-neighbor RTAB-Map keyframe poses. They are generated as:

1. Read every `/oak/rgb/image_raw` header timestamp from the raw bag.
2. Read high-frequency `/rtabmap/odom` from the baseline processed bag.
3. Read all `/rtabmap/mapData` messages from the baseline processed bag and accumulate `node_id -> node_stamp`.
4. Use the final `/rtabmap/mapData.graph` optimized poses.
5. For each optimized keyframe:

   ```text
   C(t_key) = T_map_oak_optimized(t_key) * inverse(T_odom_oak(t_key))
   ```

6. Interpolate `T_odom_oak(t)` at each RGB timestamp.
7. Interpolate correction `C(t)` between optimized keyframes.
8. Compute:

   ```text
   T_map_oak(t) = C(t) * T_odom_oak(t)
   T_map_rgb_optical(t) = T_map_oak(t) * T_oak_rgb_optical
   ```

This gives RGB poses at RGB timestamps while still anchoring them to the final optimized RTAB-Map graph. In the high-resolution export, only the cloud topic is taken from `--cloud-bag`; pose generation still uses `--processed-bag`.

Current thresholds:

```text
max_odom_gap_sec = 0.5
max_correction_gap_sec = 5.0
max_correction_extrapolation_sec = 2.0
```

These are recorded in `metadata.json`.

## Known Caveats

- Use `valid == 1` only. Invalid rows still have images but no reliable pose.
- Timestamps are ROS message header timestamps, not rosbag receive timestamps.
- JPEG export is lossy. Regenerate with PNG if exact image pixels are required.
- The exported map cloud is a global map cloud in `map`, not a per-image depth cloud.
- The cloud is not colored by the external RGB camera; colors come from the RTAB-Map cloud topic.
- The pose is for `oak_rgb_camera_optical_frame`, computed through the static OAK RGB extrinsic.
- A high-resolution cloud bag can be valid even if it does not contain `/rtabmap/mapData`; use `--processed-bag` for pose/mapData and `--cloud-bag` for high-resolution cloud topics.
